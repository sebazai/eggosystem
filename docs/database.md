# Kanaliiga Database Schema

This document provides an overview of the Kanaliiga database schema, including table structures, relationships, and design decisions. Generated by LLM.

## 1. Overview

The Kanaliiga database is designed to support a corporate Counter-Strike ladder. It manages game seasons, teams, players, matches, and statistics. The primary users of this system are Steam users (players), and each company has an admin responsible for team registrations.

## 2. Tables and Relationships

### Games

- **Purpose**: Stores unique games played in the league.
- **Columns**:
  - `id` (INT, PK)
  - `name` (VARCHAR) - Full game name.
  - `abbreviation` (VARCHAR, UNIQUE) - Unique short identifier (e.g., "CSGO").

### Seasons

- **Purpose**: Defines a season, always linked to one game.
- **Columns**:
  - `id` (INT, PK)
  - `game_id` (INT, FK → Games.id)
  - `name` (VARCHAR) - Short identifier (e.g., "Season 11").
  - `full_name` (VARCHAR) - Full name (e.g., "Counter-Strike Season 11").

### Leagues

- **Purpose**: All possible leagues.
- **Columns**:
  - `id` (INT, PK)
  - `name` (VARCHAR)

### SeasonLeagues

- **Purpose**: Represents different tiers within a season (e.g., Pro, Amateur).
- **Columns**:
  - `season_id` (INT, FK → Seasons.id)
  - `league_id` (INT, FK → Leagues.id)
  - `tier` (INT) - Defines ranking order, where Tier 1 is the highest level.
  - `external_id` (VARCHAR) - Season.platform.external_id for this SeasonLeague

### Organizations

- **Purpose**: Represents organizations with teams in the league.
- **Columns**:
  - `id` (INT, PK)
  - `name` (VARCHAR)
  - `organization_code` (VARCHAR, UNIQUE) - Unique business identifier.
  - `admin_steam_id` (BIGINT, FK → SteamPlayers.steam_id) - Admin's Steam ID.

### Teams

- **Purpose**: Represents a team, always belonging to one company.
- **Columns**:
  - `id` (INT, PK)
  - `organization_id` (INT, FK → Organizations.id)
  - `name` (VARCHAR)

### SteamPlayers

- **Purpose**: Stores Steam users participating in the league.
- **Columns**:
  - `steam_id` (BIGINT, PK) - Unique Steam identifier.
  - `nickname` (VARCHAR)
  - `email` (VARCHAR)
  - `work_email` (VARCHAR)
  - `discord` (VARCHAR)
  - `full_name` (VARCHAR)

### PlayerStats

- **Purpose**: Stores Steam users statistics for each played map.
- **Columns**:
  - `steam_id` (BIGINT, PK) - Unique Steam identifier.
  - `game_id` (INT, FK → MatchGames.id)

### SeasonTeamRegistrations

- **Purpose**: Links teams to seasons, recording registration details.
- **Columns**:
  - `season_id` (INT, FK → Seasons.id)
  - `team_id` (INT, FK → Teams.id)
  - `captain_steam_id` (BIGINT, FK → SteamPlayers.steam_id)
  - `co_captain_steam_id` (BIGINT, FK → SteamPlayers.steam_id)
  - `defects` (TEXT) - Notes from captain.
  - `ticket` (VARCHAR) - Manual ticketing reference.
  - `approved` (BOOLEAN) - Indicates if the team is officially registered.
  - `notification_sent` (BOOLEAN) - Indicates if additional information is required.

### SeasonLeagueTeams

- **Purpose**: Assigns teams to specific leagues after registration closes.
- **Columns**:
  - `season_team_id_fk` (INT, FK → SeasonTeamRegistrations.id)
  - `season_league_id_fk` (INT, FK → SeasonLeagues.id)

### SeasonTeamPlayers

- **Purpose**: Tracks which players belong to which teams in a season.
- **Columns**:
  - `season_id` (INT, FK → Seasons.id)
  - `team_id` (INT, FK → Teams.id)
  - `steam_id` (BIGINT, FK → SteamPlayers.steam_id)
  - `role` (ENUM) - 'primary' or 'substitute'.

**Business Rule:**

- A player can only be a **primary** player for one team per season. This is enforced via a **trigger** that checks for this condition when inserting or updating records.

### Matches

- **Purpose**: Parent match. A match can have multiple MatchGames. BO1, BO3, BO5 etc.
- **Columns**:
  - `stage` 1 = regular, 2 = playoff
  - `match_date`

### MatchTeams

- **Purpose**: Links matches and teams, allowing flexibility for different game modes.
- **Columns**:
  - `match_id` (INT, FK → Matches.id)
  - `season_id` / `league_id` (INT, FK → SeasonLeagues)

### TeamGameScores

- **Purpose**: Records scores for each team in a match.
- **Columns**:
  - `match_id` (INT, FK → Matches.id)
  - `team_id` (INT, FK → Teams.id)
  - `score` (INT) - Final score.
  - `overtime_score` (INT)
  - `halftime_score` (INT)
  - `starting_side` (ENUM) - 'CT' or 'T'.

**Business Rule:**

- Could be derived from MapRoundStats. However, for historical reasons, TeamGameScores is saved separately.

### MatchGames

- **Purpose**: Tracks individual maps played within a match.
- **Columns**:
  - `match_id` (INT, FK → Matches.id)
  - `map_id` (INT)
  - `demo_file` (VARCHAR) - Link to the game demo file.

**Relation to old Kana db structure**

- This is same as matches table in old Kana.

### MapRoundStats

- **Purpose**: Track each round related statistics, which side won etc.
- **Columns**:
  - `ct_team_id` (INT) - Which team played CT side on this round.
  - `t_team_id` (INT) - Which team played T side on this round.
  - `round_number` (TINYINT UNSIGNED) - Unique round_number for MatchGames.id.
  - `round_end_reason_info`(TINYINT UNSIGNED) - Number 1-5, why the round ended.
  - `first_kill` (VARCHAR) - CT or T.
  - `plant_site` (CHAR) - A or B bombsite.
  - `ct_t` (JSON) - Contains who were alive on CT and T side using Player.steam_id when bomb was planted.
    - This column should be parsed into a new table.

**Business rule:**

- If plant_site is defined, ct_t can not be NULL.
- If round_end_reason_info is 1,2 - plant_site can not be NULL.
- round_end_reason_info explanations:
  - 1: Bomb defused (CT Won)
  - 2: Target bombed (T Won)
  - 3: Target saved (CT Won. Terrorist ran out of time.)
  - 4: Terrorists win (Killed CT)
  - 5: Counter-Terrorists win (Killed T)

**Relation to old Kana db structure**

- This is same as afterplants & roundinfo table in old Kana.

### Reservations / MatchReservations

- **Purpose**: Allows streamers to reserve matches for broadcasting.
- **Columns**:
  - `match_id` (INT, FK → Matches.id)
  - `stream_link` (VARCHAR)
  - `reservation_time` (DATETIME)

**Business rule:**

- Multiple streamers can reserve a stream for the same match.

## 3. Business Rules and Design Decisions

- **Role of 'Ranks'**: The 'Ranks' table, as shown in the schema diagram, plays a role in tracking team standings or performance metrics. While not explicitly covered in the earlier sections, it is an important part of the database structure and should be considered in future expansions or modifications.

- **Game Abbreviation:** Each game is uniquely identified by its abbreviation (e.g., "CSGO").
- **Seasons Are Game-Specific:** A season always belongs to one game.
- **Tier System in Leagues:** Tier 1 is the highest ranking league.
- **Player Role Restriction:** A player can only be a primary player for one team per season, enforced via a trigger.
- **Match Structure:** Matches can contain multiple maps, supporting BO1, BO3, and BO5 formats.
- **Streaming Reservations:** Streamers can schedule matches for broadcast.

## 4. Conclusion

This schema effectively supports the management of Kanaliiga's competitive Counter-Strike ladder by organizing teams, seasons, and matches while enforcing key business rules. Future enhancements may include features for sponsors and deeper statistical tracking.
